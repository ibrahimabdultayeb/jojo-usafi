# Languages

Jojo Usafi is bilingual: **English at `/`**, **Kiswahili at `/sw/`**.

```bash
npm run i18n:check     # both dictionaries carry the same keys and placeholders
```

## Agreed terminology

| English | Kiswahili |
| --- | --- |
| Cart | **Kikapu** |
| Checkout | **Kamilisha Agizo** |
| Order | **Agizo** |

## Route shape

English is the default and is unprefixed; Kiswahili is prefixed. Every customer-facing
route exists in both, so switching language never loses the page.

| English | Kiswahili |
| --- | --- |
| `/` | `/sw` |
| `/shop` | `/sw/shop` |
| `/product/[slug]` | `/sw/product/[slug]` |
| `/cart` | `/sw/cart` |
| `/checkout` | `/sw/checkout` |
| `/track-order` | `/sw/track-order` |
| `/contact` | `/sw/contact` |

Each language has its **own root layout** (`src/app/(en)/layout.tsx`,
`src/app/(sw)/layout.tsx`) so `<html lang>` is `en` or `sw-TZ` in the static HTML rather
than corrected after hydration. Both render the same `StorefrontLayout`, and every route
file is a thin wrapper around a shared view in `src/views/` — one implementation per page.

## Canonical and hreflang

Every page emits its own canonical plus the full alternate set, built by
`localeAlternates()` in `src/lib/i18n/config.ts`:

```html
<link rel="canonical"  href=".../sw/shop"/>
<link rel="alternate" hrefLang="en"        href=".../shop"/>
<link rel="alternate" hrefLang="sw-TZ"     href=".../sw/shop"/>
<link rel="alternate" hrefLang="x-default" href=".../shop"/>
```

The absolute base comes from `NEXT_PUBLIC_SITE_URL` and falls back to the dev server. No
production domain has been chosen, so none is invented.

## Choosing and remembering a language

- **First visit** — `LanguageGate` shows a chooser dialog. Nothing renders on the server,
  so there is no hydration mismatch and no flash for returning visitors.
- **Remembered** — the choice is stored in `localStorage` under `jojo-usafi.locale.v1`.
- **Honoured once per session** — if the stored language differs from the page being
  viewed, the visitor is moved to their language once, guarded by a `sessionStorage` flag
  set *before* navigating so it can never loop. After that the URL wins, because a shared
  link is an explicit request for a language.
- **Switching** — the EN/SW switcher (header on desktop, menu on phones) strips the
  language prefix, rebuilds the same path in the other language and carries the query
  string across. The cart is keyed by SKU in `localStorage`, so it is language-independent
  and survives the switch.

## What is translated, and what is not

**Translated:** all interface copy — navigation, hero, sections, forms, cart, checkout,
tracking, contact, errors, empty states and accessibility labels. 211 keys.

**Not translated — English fallback by design:** product names, brand names, pack sizes,
category names and product descriptions. These are owned by the Product Master and exist
in English only. Translating them here would mean inventing catalogue data the master does
not hold. When the database carries Kiswahili catalogue content, it will come from there.

## Adding copy

1. Add the key to `src/lib/i18n/dictionaries/en.ts`. Its shape defines the `Dictionary`
   type, so TypeScript immediately fails until Kiswahili has it too.
2. Add the Kiswahili string to `sw.ts`.
3. Run `npm run i18n:check`. It verifies matching keys, matching `{placeholders}`, equal
   array lengths, no empty strings, and flags anything left identical to the English.

Placeholders are filled with `fill()` from `@/lib/i18n`:

```ts
fill(t.hero.body, { area: site.serviceArea })
```

A placeholder with no matching value is left visible rather than blanked, so a mistake
shows up loudly in QA instead of silently deleting copy.
