# Jojo Usafi continuous audit — 19 November 2026

## Scope and scoring

Staging branch only. Review actual storefront in the browser, inspect real admin components with synthetic fixtures where authentication is unavailable, fix defects, retest and save checkpoints. No live orders, stock, staff passwords, or shop settings changed.

This is a qualitative product review, not a certification. Five equally weighted categories: layout/readability, workflow clarity, feedback/motion, accessibility/responsiveness, and resilience/error recovery. Starting scores 7 / 6 / 7 / 6 / 6 = **6.4/10**. Production readiness is reported separately; a visual score does not establish it.

## Baseline findings

- Cart drawer: on a 454 × 312 CSS viewport the product list collapses to zero height because the fixed header/footer consume all available height. Full cart controls can crowd the price on narrow screens.
- Cart drawer product names deliberately used truncation. Long labels need wrapping.
- Persisted basket allowed duplicate SKUs, fractional/unbounded quantities and non-finite numbers. New-line add did not enforce its existing 99-unit storefront cap.
- Quantity increment controls remained enabled at the cap and could exceed the catalogue's available stock before checkout rejected them.
- Mobile header search only closed on pathname change; a second search on /shop leaves the panel open.
- Live tracking validation erased both entered fields after a phone validation error (tested JU-AUDIT / 123, no customer lookup).
- Swahili footer and other shared delivery copy interpolate an English service-area string.
- Tracking exposes a WhatsApp help link to the placeholder 255700000000. Contact settings are a launch dependency, not an excuse to link customers to fake details.

Verification:

- Four regression tests cover malformed persistence, duplicate/capped quantities, normalization stability and stock limits.
- Typecheck, lint and 270-key bilingual parity passed before checkpoint. All 237 tests and the offline schema check passed; Next.js production build generated 220 pages.

Pending next passes: placeholder contact paths; quote/submit error recovery; checkout empty state; tracking localization; admin detail/actions and shared fields; dropdown keyboard/focus behavior; animated list stability and reduced motion; launch blockers.

## Checkpoint 2 — checkout and support paths

- Unconfigured WhatsApp, phone and email channels no longer send shoppers to sample contact details. Contact page has an honest unavailable state and lists actual active delivery zones/prices. Footer delivery link opens that list.
- Empty checkout points back to shopping. Read-only price requests time out after 20 seconds and expose a retry. Failed submissions retain fields, reprice the basket, and bring the error into focus; in-flight fields cannot be edited.
- Payment radio indicator now follows its checked state. Removed the unsupported promise of an emailed receipt; corrected English name placeholder and added server email-format validation.
- Tracking preserves entered details, localizes validation and lookup errors, hides stale results during lookup, and handles transport failures without exposing internal errors.
- Live staging read-only checkout: one Multix 5LT at TSh 34,000 plus Upanga delivery TSh 4,000 produced TSh 38,000 and enabled the place-order button after pricing completed. No order submitted.
- Isolated real-component UI: forced quote failure → retry → successful quote; simulated failed submit showed pending loader/disabled fields, retained name/address/payment/zone and focused the error. Payment dot checked correctly. No horizontal overflow at 340 CSS px. These are UI checks with stubbed responses, not database persistence tests.
- All 243 tests (18 files), typecheck, lint, 275-key language parity and 220-page production build passed.

Reassessment after checkpoints 1–2: layout/readability 7.4, workflow clarity 7.2, feedback/motion 7.4, accessibility/responsiveness 7.2, resilience/error recovery 7.0 = **7.24/10**. Meaningful progress; live end-to-end order mutation, admin authentication and launch configuration still unverified in this pass.

## Checkpoint 3 — readable admin details and reliable editing

- Order detail item names are 16px; metadata is 14px; delivery/payment details and activity are larger and wrap. Product-list names/SKUs no longer truncate, with price/stock reflow on narrow screens. Inventory card descriptions and controls are larger.
- Product and inventory search now includes the real EAN/ITF-14 columns previously omitted despite the barcode placeholder.
- Price/stock entry no longer strips punctuation (which could turn `2.5` into `25`). Existing money parser handles formatted prices; stock parsing rejects decimals, minus signs, zero additions and excessive values, while allowing zero physical counts. Validation is also applied server-side before stock RPCs. Offer-price validation now rejects invalid/negative amounts.
- Product visibility/featured/archive states update only after a successful save. A synchronous in-flight guard prevents overlapping writes; stock fields and cancel controls disable during saving.
- Order dialogs remain mounted for their exit animation, then discard their drafts. Focus returns to the triggering action after close.
- UI evidence: 16px item name measured; barcode `0700000000001` selected exactly its fixture product; 454px inventory/cards had no horizontal overflow; ArrowDown/End/Enter selected the final brand and filtered results; `2.5` stock and price inputs preserved the input with an explanatory error; failed Featured save kept the switch false; closing a dialog restored focus to Cancel order and restored body scrolling.
- All 245 tests, typecheck, lint and the 220-page production build passed. Admin tests use synthetic fixtures and non-mutating stub responses; authenticated persistence is still a separate gate.

Reassessment: 7.9 / 7.6 / 7.6 / 7.7 / 7.2 = **7.6/10**. Main remaining audit work: failure/404 navigation, storefront motion and responsive review, honest launch blockers.
